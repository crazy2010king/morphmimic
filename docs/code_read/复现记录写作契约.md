# 复现记录写作契约（S09-T2 立的判定口径）

> 本文件是 `repro/lib/doc.py` 的**人类可读镜像**：校验器（`repro/28_doc_verify.sh verify`）
> 按此契约逐条断言文档；写正文（`docs/code_read/MorphMimic完整复现记录.md`）时**逐条对照本文件**，
> 不要凭印象写。
>
> 契约的唯一实现是 `repro/lib/doc.py`（stdlib only）。若本文件与代码不一致，**以代码为准**，
> 并回填本文件。

## 0. 固定失败原因集合（`doc.REASONS`）

失败时只打印一行 `DOC_VERIFY_FAIL reason=<集合内的值>`，且**零 OK marker**。

计划要求的 17 个必备 reason 全部在内：`doc-missing` / `doc-empty` / `section-missing` /
`evidence-path-missing` / `evidence-marker-missing` / `sha-mismatch` /
`eval-row-count-mismatch` / `compare-row-count-mismatch` / `completion-mismatch` /
`curve-missing` / `curve-step-missing` / `token-leaked` / `process-replication-missing` /
`unexecuted-section-missing` / `deviation-section-missing` / `mirror-missing` / `mirror-mismatch`。

另有本实现细化的 reason：`evidence-table-missing` / `evidence-table-malformed` /
`evidence-row-invalid` / `sha-missing` / `eval-csv-missing` / `eval-csv-parse-failed` /
`compare-missing` / `compare-parse-failed` / `compare-delta-mismatch` / `curve-parse-failed`。

## 1. 九章结构（`section-missing`）

每章由成对 marker 圈定，**marker 缺失即该章缺失**：

```
<!-- DOC_SECTION:1 -->   ...   <!-- /DOC_SECTION:1 -->
```

九章的 `n` 与标题（`doc.SECTION_TITLES`）：

| n | 标题 | 必填内容 |
|---|------|----------|
| 1 | 环境事实表 | — |
| 2 | 每阶段命令原文与关键输出 | — |
| 3 | 对 README 的偏离清单 | ≥ 20 条偏离（markdown 表格数据行，表头/分隔行不计） |
| 4 | 已分析未执行清单 | 必须出现 `PICO`、`真机`、`x2`、`t2` 四个 token |
| 5 | 产物路径与 SHA-256 | — |
| 6 | 训练曲线数据 | — |
| 7 | eval 对照表 | 必须逐指标引用 Δ 均值（见 §5） |
| 8 | 踩坑记录 | — |
| 9 | 明文 token 撤销提醒 | — |

> 章节正文的标题写法自由（`## 3. 对 README 的偏离清单` 之类），**判定只看 marker**。

## 2. 首页声明（`process-replication-missing`）

首页（第一章 marker 之前的正文，**或第 1 章正文内**）必须同时出现：

- `流程复现`
- `非数值等价复现`

推荐写法：**流程复现，非数值等价复现**。

## 3. 证据索引表（`evidence-table-missing` / `evidence-table-malformed` / `evidence-row-invalid` / `evidence-path-missing` / `evidence-marker-missing`）

文档中必须有一张被 marker 圈定的四列表格：

```
<!-- DOC_EVIDENCE_TABLE_START -->
| 结论 | 复现命令 | 证据文件（相对仓库根） | 关键输出（须能在证据文件中 grep 到） |
|---|---|---|---|
| ... | ... | ... | ... |
<!-- DOC_EVIDENCE_TABLE_END -->
```

逐行断言（**任一不满足即失败**）：

1. 表头行（首行 `结论` 开头）被自动剔除；表头行与分隔行不计入 `evidence_rows`。
2. 每行必须恰好 4 列（否则 `evidence-table-malformed`）。
3. `结论` 列与 `复现命令` 列**非空**（去空白后），否则 `evidence-row-invalid`。
4. `证据文件` 列：相对**仓库根**解析；文件必须存在（`logs/` `runs/` `out/` `assets/` 是 seed store
   软链，**会被跟随**），否则 `evidence-path-missing`。
5. `关键输出` 列：必须是该证据文件内容的**大小写不敏感子串**，否则 `evidence-marker-missing`。
   证据文件可能是二进制/大文件，按文本读取（`errors="replace"`）。

## 4. 明文 token（`token-leaked`）

正文（整篇，含表格与 marker）**不得**匹配正则 `hf_[A-Za-z0-9]{20,}`。

注意：写「正则本身」是安全的（`hf_[A-Za-z0-9]{20,}` 中的 `[` 不是字母数字，不会命中），
但**绝不能**写出任何形如 `hf_` + 20 位以上字母数字的示例串。

## 5. 数字必须被重算比对（不采信文档自述）

| 事实 | 来源（重算） | 期望 |
|------|--------------|------|
| 两张 eval CSV 行数 | `runs/eval/eval_motion_1h.csv` / `eval_human_full_1h.csv` | 各 490（`eval-row-count-mismatch`） |
| completion | 由两张 CSV 的 `failed` 列**重算** | 1.0（`completion-mismatch`） |
| 对照表行数 | `runs/official/compare_self_vs_official.csv` | 49（`compare-row-count-mismatch`） |
| Δ 均值 | 由对照表 `delta_*` 三列**重算** | 文档必须逐指标引用（`compare-delta-mismatch`） |
| SHA-256 | `out/g1_amber/SHA256SUMS`、`runs/official/morphmimic_policy/SHA256SUMS` | **重算**摘要一致（`sha-mismatch` / `sha-missing`） |
| 曲线 step 覆盖 | `runs/train_curves/g1_amber_1h_curves.csv` | last = 26413，first ≤ 50（`curve-step-missing`） |

### Δ 均值的引用格式（`compare-delta-mismatch`）

重算值必须出现在**同一行**内——该行同时含指标名与数值：

```
| joint_err_rms_rad | 0.012368 |
| body_err_mean_m | 0.000147 |
| end_drift_m | -0.049362 |
```

接受的数值写法：`%.6f` / `%.5f` / `%.4f` / `%.3f` / `%.2f` / `repr()`（例如 `-0.049362`）。

当前真实值（重算自 `runs/official/compare_self_vs_official.csv`，49 行）：

| 指标 | Δ 均值 |
|------|--------|
| `joint_err_rms_rad` | `0.012368` |
| `body_err_mean_m` | `0.000147` |
| `end_drift_m` | `-0.049362` |

> 每次改文档前先跑 `bash repro/28_doc_verify.sh report`，它打印 `DOC_REPORT_DELTA delta_<metric>=<值>`，
> 直接抄即可，避免手抄错。

## 6. 判定顺序（决定失败时给出哪个 reason）

```
doc-missing → doc-empty → token-leaked → section-missing →
process-replication-missing → deviation-section-missing →
unexecuted-section-missing → evidence-table-missing →
evidence-table-malformed → evidence-row-invalid → evidence-path-missing →
evidence-marker-missing → sha-missing → sha-mismatch →
eval-csv-missing → eval-row-count-mismatch → completion-mismatch →
compare-missing → compare-parse-failed → compare-row-count-mismatch →
compare-delta-mismatch → curve-missing → curve-parse-failed → curve-step-missing
```

第一个失败即终止，后面的检查不再执行。

## 7. 编排器与镜像

- `bash repro/28_doc_verify.sh verify`：**只**校验仓库内镜像
  `docs/code_read/MorphMimic完整复现记录.md`（容器内 `docs/code_doc` 软链断链，故不得依赖它）。
  成功：`DOC_VERIFY_OK sections=9 evidence_rows=N sha_ok=1 eval_rows=490 compare_rows=49 curve_rows=M`。
- `bash repro/28_doc_verify.sh mirror`：比对 `docs/code_doc/MorphMimic完整复现记录.md` 与镜像的
  sha256。成功：`DOC_MIRROR_OK mirror_match=1`；失败：`DOC_MIRROR_FAIL reason=mirror-missing|mirror-mismatch`。
- `bash repro/28_doc_verify.sh report`：打印 `DOC_REPORT_*`（供回填的数值），**不含**门禁 marker。
